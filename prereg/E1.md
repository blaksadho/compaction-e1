## Design

- **Task.** Each chain: 10 rounds. $D_1$ contains 16 planted facts (descriptor + random 8-symbol code) inside
  60 lines of synthetic operations logs; each later chunk contains 4 fresh facts in 60 new log lines. Each round the
  compactor rewrites (previous summary, new chunk) into a new summary of at most $B$ words (hard truncation).
- **Paired material.** Chain $c$ uses seed $20261104+c$ in every arm, so arms see identical facts and chunks.
- **Arms** (30 chains each):

| family | arms |
|---|---|
| budget × instruction (Haiku 4.5, Sonnet 4.6) | $B\in\{150,400\}$ × {plain, verbatim, pinned with $P=0.4B$} |
| fact load (Haiku 4.5, Sonnet 4.6) | $B=150$, plain, $K\in\{8,32\}$ initial facts |
| mechanical baseline | format-aware extraction, $B\in\{150,400\}$ |
| local open model (Qwen2.5-1.5B-Instruct Q4_K_M, CPU) | $B=400$ × {plain, verbatim} |

- **Sampling.** Compactors at temperature 1.0 (Anthropic default; same for the local model). The interpreter probe
  is Haiku 4.5 at temperature 0 for every arm, so `bound` measures the state, not the interpreter.
- **Probes.** Every round: string scores for every fact planted so far, plus one interpreter probe over all planted
  descriptors and 4 never-planted descriptors, in shuffled order.

## Outcomes

Primary (string-level, model-free): `present` (exact code substring in the truncated state).
Derived per arm: $S(g)$ for the 16 initial facts, per-generation survival $s_g$ (all facts), half-life,
within-round contrasts $d_{1w}$ and $d_{2w}$.
Secondary: `bound` (interpreter retrieves the exact code), `mutated`, hallucination rate on never-planted
descriptors, overflow rate, `present_untruncated` (rescoring without truncation).

## Hypotheses and decision rules

All CIs are 95% percentile bootstrap intervals with chains as the resampling unit (2000 replicates, seed 1;
`python3 -m harness.analyze`). Bootstrap p-values are the sign test $2\min(P^*(x\le0),P^*(x\ge0))$.

**Confirmatory family** (Holm–Bonferroni at $\alpha=0.05$ across the 8 tests: 2 contrasts × 2 API models × 2 budgets,
plain arms only):

1. **H1 vs H0 (first compaction differs).** Statistic $d_{1w}$ = mean over rounds $r\ge2$ of
   [survival of raw facts entering their first compaction] − [survival of already-summarized facts in the same
   round]. Same round means same summary load, so this is free of the load confound.
   H0 (constant contraction) is rejected in favour of H1 if Holm-adjusted $p<0.05$; the sign gives the direction
   ($d_{1w}<0$: capacity cut at the first compaction, as in [3, 4]; $d_{1w}>0$: faster loss after round 1, as in the
   400-word arm of [3]).
2. **H2 (generation drift).** $d_{2w}$ = mean over rounds $r\ge3$ of [survival at generation 2] − [survival at
   generations $\ge3$] within the round. $d_{2w}>0$ with Holm-adjusted $p<0.05$ supports H2 (older summarized content
   is less stable), i.e. generation-dependent contraction $\eta_g$ in Theorem B.

**Confirmatory predictions from the theory** (each a paired contrast on shared seeds, `--pair`, 95% CI must
exclude 0 in the stated direction; not Holm-adjusted, reported as a separate family):

3. **Noiseless sub-channel (Theorem B escape).** $S_{\text{pinned}}(10)-S_{\text{plain}}(10)>0$ at each $B$ and model.
4. **Verbatim instruction.** $S_{\text{verbatim}}(10)-S_{\text{plain}}(10)>0$ at each $B$ and model.
5. **Budget.** $S_{B=400}(10)-S_{B=150}(10)>0$ for plain arms.
6. **Load (capacity).** $S_{K=8}(1)>S_{K=16}(1)>S_{K=32}(1)$ for plain $B=150$ arms, judged by the pooled point
   estimates with non-overlapping CIs between $K=8$ and $K=32$.

**Descriptive (no decision rule).** Pooled $s_g$ curves and the H0/H1 binomial LRT (ignores within-chain dependence);
OLS slope of $s_g$ on $g\ge2$; mutation rates (expected $<2\%$ of facts, following [3]); resurrections (expected 0;
any nonzero count is reported with the trace); which facts the pinned arms choose to pin (input to B1); local-model
arms; mechanical baseline.

## Operational rules

- Run order: `configs/e1.json` with concurrency 6, then `configs/e1_local.json` with concurrency 1.
- Chains that end with `status: error` are re-run by re-invoking the runner (it resumes), at most 3 attempts per
  chain. A chain failing 3 times is excluded and reported. Summaries are never filtered or edited.
- Budget cap: $150 for `e1.json` (estimated $95 from smoke token counts: about $0.10 per Haiku chain and $0.25 per
  Sonnet chain). If the cap stops the run, completed arms are analysed and the shortfall is reported.
- No interim analysis of E1 outcomes before all chains of `configs/e1.json` finish; progress monitoring is limited
  to chain status and cost.
- Local arms run on CPU (4 threads): the smoke run took ≈110 s per compaction call at $B=150$, so the 60 local
  chains need roughly two days. They are descriptive only; the smoke chain retained no codes at $B=150$, so a floor
  effect is possible.

## Deviations

1. **Local-arm inference host (logged 2026-11-03, before any `configs/e1_local.json` chain ran).** The local model
   server moves from this machine's CPU (llama.cpp b12065, 4 threads) to a Mac mini M4 Pro, 64 GB (Homebrew
   llama.cpp 0.7.0, build 11669, commit 620d2225c, Metal, `-ngl 99`). Unchanged: the GGUF (SHA-256
   `6a1a2eb6d15622bf3c96857206351ba97e1af16c30d7a74ee38970e434e9407e`, verified on both hosts), the server flags
   `-c 8192 --seed 1`, `configs/e1_local.json` and its hash, and all harness code. The harness still runs here and
   reaches the server through an SSH tunnel at the registered `base_url` `http://127.0.0.1:8081/v1`. Reason: speed.
   Measured 1,699 prompt tokens/s and 136 generated tokens/s, so a compaction call takes about 5 s instead of
   about 110 s. Effect on inference: none expected. Compactors sample at temperature 1.0, so outputs are not
   reproducible across backends in either case. The run order (API arms first) is unchanged.
2. **Pinned-response parser (logged 2026-11-05, after all registered E1 and Addendum A chains had finished).**
   Change to `harness/compactors.py`, whose SHA-256 moves from `28c0b11c59114004db72d64393207245a0f207c749ac864b26fef02b9d89eec6` to
   `238677e3aae8c3b98ab0d4a529c44f552f8180980d99b34d3e4aa826531eb4f8`. Two parts:
   - `_parse_pinned` also accepts tag-form sections (`<PIN>`, `<pinned>`, `<SUMMARY>` and their closing tags, any
     case) as the `PIN:`/`SUMMARY:` headers.
   - `LLMCompactor.compact` skips new pins that exactly repeat a pin already carried.

   Reason: Qwen2.5-32B answered in the prompt's tag style in 35% (B150) and 67% (B400) of pinned compaction calls,
   so the old parser pinned nothing in those rounds (`notes/e1_results.md`, Addendum A).

   Effect on registered arms: none. Replaying every logged response of the 4 Haiku/Sonnet pinned arms through the
   new code reproduces all 1,200 logged states exactly. The old code reproduces all 1,800 pinned-arm states,
   including Qwen's, which confirms the replay is faithful. All registered results stand as computed with the old
   parser, including the reversed A3. The new parser is used only for the Addendum B arms (`prereg/E1-open-B.md`).
